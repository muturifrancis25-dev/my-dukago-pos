Add staff

Each person needs their own PIN — signing in is PIN-only, so My DukaGO POS identifies who's signing in from the PIN itself. No duplicates allowed.

Roles, in short

Cashier — sells only, 4-digit PIN. Voiding a line or clearing a cart needs sign-off.
Supervisor — everything a cashier can do, plus can approve voids with their own 4-digit PIN.
Admin — full access: Stock, Reports, Sync setup, and assigning everyone else's role. Admin PINs are 6 digits — longer on purpose, so it's harder for a cashier to glance at the keypad and pick it up.

Staff list

Role is a dropdown you can change any time — promote a cashier to supervisor without deleting their account. Revoke turns off someone's PIN without deleting their sales history. You can have as many active cashiers as you need.

Receipts & printer

A web page can't tell whether a printer is physically plugged in — browsers don't allow that for privacy reasons. Instead, "Print" opens the normal print dialog: if a printer is set up on this device, it shows up there and prints for real; if not, the same dialog lets you choose "Save as PDF." One button covers both cases — that's genuinely how it needs to work from a browser.

Personal backup — Google Drive

Separate from the backend above: this backs this outlet's own data up into the signed-in owner's own Google Drive — private to them, not shared with any other outlet. The backup includes the full audit log and staff list (never PINs), so an admin can open that file from any device — their laptop, another phone, anywhere — and review exactly what every cashier did since they signed in, without needing to be at the till itself. It's a snapshot from the last backup, not a live feed — for that, someone would need to trigger "Back up now" first. Needs a Google Cloud OAuth Client ID (free, one per deployment) and the page served over http/https — it won't work opened as a raw file, and Google requires your Gmail added as a "test user" on the OAuth screen until the app is verified.

Online / offline behavior

This isn't a toggle you manage day to day — it's automatic.

The till watches the device's real network state. Lose signal mid-sale and nothing changes for the cashier — sales keep ringing up, stock keeps deducting, everything queues locally. The moment the connection is back, queued sales and stock updates drain to the backend on their own. The button below is only there to test that flow on demand, without physically switching off wifi.

One thing to set up once you host this for real: the page itself needs to survive a reload with zero network too — that's what manifest.json and sw.js (included alongside this file) handle. Host all three together and open the till once while online — after that, it opens offline, cold, with no connection at all.
